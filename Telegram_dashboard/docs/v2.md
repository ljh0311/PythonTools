# Telegram Dashboard v2

Personal **awareness** UI next to the classic Operator dashboard. Goals: **Talk** (read personal threads), **Act** (attention queue + AI suggestions), **Profiles** (Markdown contact cards).

## Open which UI?

| URL | UI | Purpose |
|-----|-----|---------|
| `http://localhost:8000/` | **v1 Operator** (unchanged) | Inbox, analytics, tools, bot ops |
| `http://localhost:8000/v2` | **v2 Awareness** | Talk / Act / Profiles |

Static assets: `/v2/static/…`. From v2, **Open classic dashboard** returns to `/`.

## Start the server

From `Telegram_dashboard`:

```bash
.\.venv\Scripts\python.exe -m backend.main   # Windows
# source .venv/bin/activate && python -m backend.main
```

Default: `http://localhost:8000`. Operator auth matches v1 (session / `DASHBOARD_API_KEY`).

Cloud Agents: see [AGENTS.md](../AGENTS.md).

## What v2 covers (current)

| Area | Behavior | Key paths |
|------|----------|-----------|
| **Talk** | List `user_account` threads; open message pane; create-profile entry | `GET /api/v2/talk/threads`, `…/messages`; `frontend/v2/js/talk.js` |
| **Act** | Needs-reply triage first; open-items merge; draft suppress when already replied; AI refresh; status patch | `GET\|POST /api/v2/act…`, `PATCH /api/v2/act/{id}`; `act_reply_state.py`, `act_open_items.py`, `act.js` |
| **Profiles** | List/edit Markdown under `data/profiles/{chat_id}-*.md`; learn-from-chat refresh | `/api/v2/profiles…`; `profile_md.py`; `profiles.js` |
| **Digest** | Optional bot→operator needs-reply digest (scheduled + on-demand) | `unread_digest_service.py`; `UNREAD_DIGEST_*` env |

v1 at `/` stays the fallback; v2 does **not** replace Operator. Operator and v2 share a UI-version toggle + login polish.

## Current state (honest)

v2 is a **usable Awareness slice**: Talk/Act/Profiles plus Act triage that prefers unanswered threads and an optional Telegram digest. It is **not** yet a full personal CRM or a replacement for Operator’s inbox/tools depth.

Verified locally (2026-09-26):

- `pytest backend/tests/test_profile_md.py backend/tests/test_v2_act.py backend/tests/test_unread_digest.py backend/tests/test_ai_honesty.py backend/tests/test_providers.py` → 30 passed
- Default AI order: `AI_PRIMARY_PROVIDER=gemini` (model `gemini-3.6-flash`); Gemini 429 falls back to Ollama with keys redacted

## Gaps vs v1 Operator

| Operator (v1) strength | v2 today |
|------------------------|----------|
| Rich inbox filters, send, quick actions | Talk is still mostly **read-oriented**; reply/send incomplete |
| Live metrics, analytics, events, WebSocket-heavy ops | No metrics/analytics surfaces on `/v2` |
| Bot + user source switching in one inbox | Talk defaults to `user_account` only in UI |
| Tooling / OpenClaw / feedback panels | Out of scope for Awareness shell |

## What needs improvement (priority)

1. **Talk completeness** — reply/send composer, search/filter UI, bot vs user_account toggle, realtime updates
2. **Act usefulness** — one-click draft send; clearer empty/degraded AI states; more triage feedback in UI
3. **Profiles lifecycle** — deeper sync with store relationship fields; avoid `utcnow` deprecation warnings
4. **Data dependency** — empty Talk without MTProto ingest; document/seed path for Cloud demos
5. **Parity & polish** — mobile layout; a11y for nav/panels
6. **Tests** — Talk route tests; frontend smoke

## External context (why this shape)

Peers (e.g. Telegram-native CRMs, relationship agents) emphasize **thread↔contact stitching**, commitment nudges, and AI follow-ups. v2’s Talk/Act/Profiles split matches that mental model but is thinner: Markdown profiles and a suggestion queue are the right backbone; missing send, digests, and proactive nudges are the main product gaps—not the three-pane IA.
